# npm 发布准备审查

## 结论与边界

本轮针对首次 npm 发布准备，目标版本保持 **0.6.0**，没有执行发布、修改凭证或自动升级版本号。当前组件入口为 136 个：核心 43、扩展 80、实验 13。

本地构建、产物核对和真实 tarball 消费者验收通过。**账号侧尚不能发布**：审查时官方 registry 身份检查返回 401，包信息查询返回 404。需要维护者重新登录并确认 scope 权限；404 不能证明有权限，也不排除查询权限问题。登录后必须再次确认目标版本未被使用。

此结论不代表所有组件在所有浏览器、读屏器和动画中间帧上均已完成验收，也不代表长期稳定 API 承诺。此前移除九个薄包装的公开 API 变更见[删减记录](component-pruning.md)。

## 已修复的发布问题

1. 核心自定义元素入口缺少副作用声明，生产消费者的纯导入可能被裁掉。已在[包配置](../package.json:44)中与全量入口一起声明，并增加真实安装后的生产构建检查。
2. 核心与全量独立包各有模块状态，原先用模块内集合不能跨包避免共享组件样式重复注入。[注册逻辑](../src/utils/register-elements.js:31)改以浏览器真实注册表过滤待注册组件；双向加载检查确认构造器不替换、样式不重复。
3. 独立包内含第三方代码但未集中交付完整授权文本。[构建](../scripts/build-lib.js:1)从实际输出模块图收集包的许可证与声明，写入发布目录；当前覆盖 80 个包。二维码依赖发布包遗漏完整许可证，补存已核对的上游原文，并锁定该例外版本；升级时须重新审查。
4. Vite 从受安全告警影响的 8.3.2 升至补丁版本 8.3.5，未更换技术栈。
5. 开发依赖扫描纳入截图和历史消费者目录，且将演示文本中的脚本标签误判为代码。已限定真实入口、将文本写为安全字面量；冷启动冒烟不再输出扫描错误。
6. [使用说明](../README.md:1)修正未提交状态、语法数量、维护目标和能力边界，补充 ESM、现代浏览器、独立入口、许可证与发布前提。

### 消费者检查的准确范围

- Chromium：Vue、全量自定义元素生产构建、全量独立文件；输入/事件、弹层 Escape、嵌套菜单键盘、编辑器、二维码与实际样式。
- Chromium、Firefox、WebKit：核心入口纯副作用导入的生产构建，以及静态 HTTP 下核心独立文件；确认只注册核心档位、按钮点击、文本输入及样式。
- Chromium：核心→全量、全量→核心；已有构造器保持不变、共享样式不重复，扩展组件完成登记。
- Vue 按钮具名消费约 71,671 字节 JS，模块图不含 CodeMirror、Tiptap、KaTeX、二维码和高亮引擎；有对应引擎的正对照消费者。
- 网络、运行时与控制台错误均未在受检生产消费者中出现。Firefox/WebKit 只做核心入口小范围检查，不能外推至其余交互。

全量入口体积较大是已知限制，包含全部内容引擎，不随标签使用量裁剪。一般原生消费者优先核心入口，Vue 使用具名导入。两个独立元素入口各自内含运行时，先后混用虽可工作，仍会多下载代码。

发布清单只允许构建目录、包配置、说明和主许可证；检查核心独立文件及第三方完整声明在包内，源码、测试、站点壁纸和审查目录不入包。独立文件复制部署时还须保留对应第三方声明。

## 维护者发布步骤

1. 使用有 scope 权限的账号登录官方 npm registry，确认身份，不将凭证写入仓库。
2. 查询包及目标版本；如果版本已占用，先决定新版本，不能覆盖已有版本。更改版本后重新构建与验收。
3. 安装发布验收所需的三个 Playwright 浏览器，执行[包配置](../package.json:53)中的发布检查、默认冒烟与 SSR 命令。
4. 检查实际打包清单、README、许可证、版本和 Git 状态。不要将本地旧 tarball 当作新构建结果。
5. 由维护者手动执行发布，处理 npm 所需的双因素认证。
6. 从 registry 查询实际版本并在新项目安装复验，成功后更新发布状态。

预发布钩子会执行库构建、产物与真实安装检查；打包钩子会重建。它们不会替代账号权限校验、安全审计、人工审查或发布后的真实 registry 安装验证。
